# Lampa Tor Updater

Плагин для Lampa, который отслеживает **ту же самую раздачу** на трекере и безопасно обновляет сохранённый сериал в TorrServer, когда релизер перезаливает torrent с новыми сериями.

Главный принцип: плагин **не заменяет штатную логику Lampa**. Если нельзя доказать, что найденный результат — та же исходная раздача, ничего не меняется.

## Как это работает

1. При выборе torrent в стандартном поиске Lampa плагин запоминает идентичность release из ответа Jackett-compatible parser: `TrackerId/Tracker + Details` (или `Guid` как fallback).
2. В TorrServer сохраняется только хэшированная release identity — URL страницы трекера и magnet не сохраняются плагином.
3. При следующем открытии torrent — как из карточки сериала, так и из **«Мои торренты»** — плагин лениво запускает стандартный `Lampa.Parser.get()`.
4. Новый результат считается продолжением только при точном совпадении release identity. Название раздачи не используется как primary key.
5. Если `infohash` изменился, новый torrent сначала временно добавляется в TorrServer и проверяется по реальному `file_stats`.
6. Автообновление разрешено только когда набор распознанных эпизодов является строгим надмножеством старого: например `E01-E03 → E01-E04`.
7. Timecode переносится по логическому `SxxEyy`, а не по `file_index`.
8. Старый torrent удаляется только после успешного добавления нового и не удаляется во время активного воспроизведения. Если обновление найдено из уже открытого экрана «Мои торренты», cleanup откладывается до выхода из экрана, чтобы не оставить UI со старым hash.

Если `infohash` изменился, но новых серий нет, плагин не делает silent replacement. В long-press появляется возможность проверить и обновить revision вручную.

## Настройки

В Lampa появится раздел **«Обновление сериалов»**:

- **Следить за обновлениями раздач** — master switch;
- **Автообновление при новых сериях** — автоматическая замена только при strict-superset проверке;
- **Интервал фоновой проверки** — 1/3/6/12/24 часа; проверка выполняется lazy при открытии torrent;
- **Диагностический лог** — выводит только безопасную сводку наличия `Details/Guid/InfoHash`, не печатая URL/magnet.

В long-press меню «Мои торренты» и файлов torrent добавляется **«Проверить обновление»**. Если revision уже найден, появляется **«Обновить раздачу»**.

## Безопасная модель matching

Приоритет идентификации:

```text
TrackerId + Details
        ↓
Tracker + Details
        ↓
TrackerId/Tracker + Guid (fallback)
```

`Title`, размер и список озвучек не являются идентификатором release. Это сделано специально: у сериальной раздачи название и набор дорожек могут меняться при очередной перезаливке.

Если стабильных `Details/Guid` нет, плагин не угадывает похожую раздачу и оставляет всё штатной Lampa.

## Старые torrent без metadata плагина

Для уже существующего torrent сначала выполняется безопасный bootstrap: parser search должен вернуть результат с **тем же infohash**, после чего плагин может автоматически запомнить его release identity.

Если трекер уже обновил раздачу и старый hash больше не находится, ручное **«Проверить обновление»** запускает recovery-flow через **штатный экран поиска торрентов Lampa**. Сохраняются стандартные фильтры и сортировки (качество, HDR/Dolby Vision, озвучка, сезон, tracker и т. д.). На временной recovery-странице OK/Enter по результату означает выбор этой раздачи для проверки. После выбора плагин проверяет реальные `file_stats` и набор эпизодов. Привязка сохраняется только после явного подтверждения и совместимой проверки; после этого следующие обновления снова определяются автоматически по release identity.

## Метаданные при обновлении

При migration нового torrent:
- отображаемое имя обновляется из выбранной актуальной раздачи;
- poster обновляется из актуальной карточки Lampa;
- `data` не заменяется целиком: существующие значения сохраняются, отсутствующие дополняются;
- известные актуальные поля карточки (названия, poster/backdrop, количество серий и т. д.) освежаются;
- `torrent_follow` переносится и обновляется.

## Разработка

Требуется Node.js 20+.

```bash
npm test
npm run build
npm run check
```

Сборка создаёт:

```text
dist/plugin.js
plugin.js
```

GitHub Actions на каждый push в `main` запускает тесты, собирает `dist/plugin.js`, сохраняет build artifact и публикует `plugin.js` через GitHub Pages.

## Совместимость

Реализация ориентирована на актуальный публичный API Lampa (`Parser`, `Torserver`, `torrent`, `torrent_file`, `mytorrents`, `SettingsApi`) и TorrServer MatriX API (`/torrents`, `/viewed`). Базовая функциональность присутствует в MatriX.144.
